From /sys/bus/i2c/devices/
0-0020 → Main camera on i2c-0 (I2C address 0x20)
0-0021 → Deputy camera on i2c-0 (I2C address 0x21)
1-002a → Main2 camera on i2c-1 (I2C address 0x2A)
1-006c → Sub camera on i2c-1 (I2C address 0x6C)

i2c@70300000 {                          // Device tree address
    compatible = "sprd,sharkl5pro-i2c";  // Driver compatibility string
    reg = <0x70300000 ...>;              // Hardware register address
    
    sensor-main@20 {                     // Camera node
        compatible = "sprd,sensor-main";  // Camera driver string
        reg = <0x20>;                     // I2C slave address (0x20)
        // GPIO and voltage regulator properties
    }
}
The sprd-i2c driver:
Reads the device tree
Registers the I2C bus controller at the hardware address
Creates /dev/i2c-0 for address 0x70300000
The kernel automatically numbers them (0, 1, 2, etc.)
I2C Device Instantiation
The sprd_sensor kernel module (visible in dmesg):
Loads at boot: sprd_sensor: loading out-of-tree module
Parses device tree for camera nodes
Registers as an I2C client driver
Binds to the camera devices based on compatible strings
Creates device nodes in /sys/bus/i2c/devices/
